# Catodo 跨平台兼容性完善 - 开发笔记

## 概述

本次开发对 Catodo 应用进行了全面的跨平台兼容性适配，确保 Windows 和 Android 平台编译通过并正常运行，同时修复了 macOS、Linux、Web 等平台的已知问题。

## 一、P0 级：通知服务跨平台适配

### 问题

`flutter_local_notifications` 插件不支持 Windows 和 Linux 平台，直接导入会导致编译失败。

### 解决方案

采用**条件导入 + 抽象层**模式：

1. **`lib/services/notification_service_stub.dart`**（新建）
   - 为不支持通知的平台（Windows、Linux、Web）提供空实现
   - 所有方法均为 no-op，避免编译错误

2. **`lib/services/notification_service_io.dart`**（新建）
   - 为支持 `dart:io` 的平台（Android、iOS、macOS）提供完整实现
   - 包含初始化、调度提醒、取消提醒、重新调度等全部功能
   - 添加 try-catch 错误处理，初始化失败时静默降级

3. **`lib/services/notification_service.dart`**（修改）
   - 使用条件导出自动选择平台实现：
   ```dart
   export 'notification_service_stub.dart'
       if (dart.library.io) 'notification_service_io.dart';
   ```

### 关键点

- 条件导入是 Dart 的编译时特性，不同平台编译不同的代码，零运行时开销
- stub 的实现保持与原接口完全一致，上层代码无需任何修改

## 二、P0 级：Android 通知权限

### 问题

Android 13+ 需要在运行时请求 `POST_NOTIFICATIONS` 权限，否则通知静默失败。

### 解决方案

1. **`android/app/src/main/AndroidManifest.xml`** - 添加权限声明：

   ```xml
   <uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
   <uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>
   <uses-permission android:name="android.permission.USE_EXACT_ALARM"/>
   <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
   ```

2. **`pubspec.yaml`** - 添加依赖：

   ```yaml
   permission_handler: ^11.3.0
   ```

3. **`lib/main.dart`** - 应用启动时请求权限：
   ```dart
   await Permission.notification.request();
   ```

## 三、P0 级：macOS 网络权限

### 问题

macOS 沙盒应用默认禁止网络访问，Release 模式下 API 调用失败。

### 解决方案

在 `macos/Runner/Release.entitlements` 和 `DebugProfile.entitlements` 中添加：

```xml
<key>com.apple.security.network.client</key>
<true/>
```

## 四、P1 级：文件导入导出跨平台适配

### 问题

`data_management_screen.dart` 直接使用 `dart:io` 的 `File` 和 `Platform` 类，在 Web 平台无法编译。

### 解决方案

1. 移除 `import 'dart:io'` 和 `import 'dart:convert'`
2. 使用 `file_picker` 的跨平台 API：
   - **导入**：使用 `result.files.single.bytes` + `utf8.decode()` 替代 `File(path).readAsString()`
   - **导出**：`FilePicker.platform.saveFile()` 的 `bytes` 参数已自动处理文件写入，移除 `dart:io` File 的 fallback 逻辑

### 关键点

- `file_picker` 的 `withData: true` 参数确保在所有平台返回 `bytes`
- `saveFile` 方法在移动端和桌面端均弹出系统保存对话框，Web 端触发下载

## 五、P1 级：桌面端响应式布局

### 问题

桌面端窗口较宽时，底部导航栏（BottomNavigationBar）体验不佳。

### 解决方案

新建 `lib/ui/components/adaptive_navigation.dart` 组件：

- 窄屏（< 600dp）：使用 `NavigationBar`（Material 3 底部导航）
- 宽屏（>= 600dp）：使用 `NavigationRail`（侧边导航栏）+ 垂直分割线

使用 `LayoutBuilder` 根据实际可用宽度自动切换布局模式。

## 八、Android 构建问题修复

### 问题

`file_picker`、`isar_flutter_libs`、`flutter_plugin_android_lifecycle` 等插件的 `compileSdk` 版本过低，导致 AAR metadata 检查失败。

### 临时修复

在 pub cache 中直接修改三个插件的 `build.gradle`：

- `file_picker-8.0.7`: `compileSdk 34` → `36`
- `flutter_plugin_android_lifecycle-2.0.35`: `compileSdk = flutter.compileSdkVersion` → `36`
- `isar_flutter_libs-3.1.0+1`: `compileSdkVersion 30` → `36`

同时在 `android/app/build.gradle.kts` 中：

- 启用 `isCoreLibraryDesugaringEnabled = true`
- 添加 `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")`
- 设置 `compileSdk = 36`, `minSdk = 21`

### 长期方案

后续应升级 `file_picker` 和 `share_plus` 到最新版本，但需解决 `win32` 包的版本冲突问题。

## 十、架构总结

```
lib/
├── main.dart                          # 应用入口，窗口/权限初始化
├── services/
│   ├── notification_service.dart      # 条件导出（平台选择）
│   ├── notification_service_io.dart   # Android/iOS/macOS 实现
│   └── notification_service_stub.dart # Windows/Linux/Web 空实现
└── ui/
    ├── components/
    │   └── adaptive_navigation.dart   # 响应式导航组件
    └── screens/
        └── data_management_screen.dart # 跨平台文件导入导出
```

关键技术模式：

1. **条件导入**：编译时平台选择，零运行时开销
2. **空对象模式**：不支持的平台使用 stub 实现
3. **LayoutBuilder**：响应式布局自适应屏幕宽度
4. **第三方库抽象**：通过 `file_picker` 等库屏蔽平台差异

## 十一、Android 实机崩溃问题修复（第二轮）

### 问题

Android 编译的 APK 安装到手机后完全打不开，闪退。

### 根因分析

通过代码审查，发现以下 4 个关键问题：

#### 1. `window_manager` 在 Android 上崩溃（致命）

`main.dart` 中 `windowManager.ensureInitialized()` 仅通过 `kIsWeb` 判断，但 `window_manager` 插件仅支持 Windows/macOS/Linux 桌面平台，在 Android 上调用会导致 `MissingPluginException` 崩溃。

**修复**：添加 `_isDesktopPlatform()` 函数，使用 `Platform.isWindows || Platform.isMacOS || Platform.isLinux` 精确判断桌面平台。

#### 2. `permission_handler` 权限请求可能崩溃

`Permission.notification.request()` 在旧版本 Android 或特殊设备上可能抛异常。

**修复**：外层包裹 `try-catch`，权限请求失败不影响启动。

#### 3. Isar `inspector: true` 在 Release 模式可能有问题

`database_service.dart` 中硬编码 `inspector: true`，该选项在 Release 模式下可能导致未知行为。

**修复**：改为 `inspector: kDebugMode`，仅在 Debug 模式下启用。

#### 4. `timezone` 时区数据未初始化

`notification_service_io.dart` 使用 `tz.TZDateTime.from()` 和 `tz.local`，但从未调用 `tz.initializeTimeZones()`，会导致运行时异常。

**修复**：在 `NotificationService.initialize()` 中调用 `tz_data.initializeTimeZones()`。

### 其他修复

#### 5. Release 模式 ProGuard/R8 规则

Isar 使用 JNI 原生方法，Release 模式下 R8 可能会剥离相关类。

**修复**：新建 `android/app/proguard-rules.pro`，添加 Isar 和 native 方法的保留规则，并在 `build.gradle.kts` 中启用 `isMinifyEnabled = true` 并引用规则文件。

#### 6. `minSdk` 版本明确化

将 `minSdk = flutter.minSdkVersion` 改为 `minSdk = 21`，避免 Flutter 版本变化导致兼容性问题。

## 十四、Android 16 黑屏问题修复（第三轮）

### 问题

在 Android 16（API 36）设备上安装 APK 后，打开应用显示黑屏，无法进入 UI。

### 根因分析

Flutter 3.44.0 的 `targetSdkVersion = 36`（对应 Android 16），`minSdkVersion = 24`。

排查出以下可能原因：

#### 1. `runApp()` 在异步初始化之后才调用（最可能的原因）

`main()` 函数中先 `await NotificationService().initialize()` 再 `runApp()`。如果 `flutter_local_notifications` 在 Android 16 上新原生层崩溃（SIGSEGV），Dart 的 try-catch 无法捕获，进程直接被杀，`runApp()` 永远不会被调用。用户看到的是 Launch Theme 的背景（暗色模式下为黑色）。

**修复**：重构 `main()` 函数，先调用 `runApp()` 渲染 Flutter UI，再异步初始化通知服务和请求权限。

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(const ProviderScope(child: CatodoApp())); // 先渲染 UI
  _initializeServices(); // 异步初始化，不阻塞渲染
}
```

#### 2. Android 15+ Edge-to-Edge 强制适配

Android 15（API 35）开始强制 edge-to-edge 显示。旧的 Android 主题（`Theme.Light.NoTitleBar`）不兼容。

**修复**：

- 更新 `values/styles.xml` 和 `values-night/styles.xml`，使用 Material 主题（`Theme.Material.Light.NoActionBar` / `Theme.Material.NoActionBar`）
- 添加透明状态栏和导航栏配置
- 在 `main.dart` 中添加 `SystemChrome.setSystemUIOverlayStyle` 和 `SystemChrome.setEnabledSystemUIMode(SystemUiMode.edgeToEdge)`

#### 3. `Isar.open()` 在 Android 16 上可能挂起或崩溃

Isar 3.1.0+1（2023 年）的原生库可能不兼容 Android 16。如果 `Isar.open()` 在原生层卡住，FutureProvider 会一直处于 loading 状态。

**修复**：

- 添加 10 秒超时保护：`Isar.open(...).timeout(Duration(seconds: 10))`
- 超时后抛出明确的错误信息，UI 会显示错误状态而非无限黑屏

#### 4. 全局错误处理缺失

原生层崩溃无法被 Dart 捕获，但 Dart 层的未处理异常应被记录。

**修复**：

- 添加 `FlutterError.onError` 全局错误处理
- 添加 `PlatformDispatcher.instance.onError` 捕获未处理异步错误
