## 一、方案A：全量同步 + 软删除传播

### 1.1 问题回顾

当前同步存在以下问题导致删除无法跨设备传播：

| 环节 | 文件 | 问题 |
|------|------|------|
| 发送数据 | `task_list_screen.dart#L277` | `getAllActiveTasks()` 过滤了 `isDeleted=true` 的任务 |
| 同步匹配 | `webdav_service.dart#L268-L274` | 被删任务不在 localMap 中 → 被当作"远程独有"重新下载 |
| 冲突解决 | `webdav_service.dart#L287-L296` | `_resolveConflict` 完全不处理 `isDeleted` 字段 |
| 写回本地 | `task_list_screen.dart#L284-L287` | `updateTask` 用远程 `isDeleted=false` 覆盖本地 `isDeleted=true` |

### 1.2 方案A核心逻辑

**删除优先策略**：任一方标记 `isDeleted=true` 即视为删除，传播到所有设备。

**同步流程**（修复后）：

```
1. 发送全部任务（含 isDeleted=true）参与同步
2. 按 syncId 匹配本地和远程任务
3. 冲突解决（_resolveConflict）增加软删除处理：
   - 任一方 isDeleted=true → 结果 isDeleted=true（删除传播）
   - 双方 isDeleted=true → 从合并列表移除（真删除，不再上传）
   - 双方 isDeleted=false → 按原有 SyncMode 处理
4. 合并结果写回本地：
   - isDeleted=true 的任务 → softDeleteTask
   - isDeleted=false 的任务 → updateTask
5. 上传合并结果到云端
```

**多设备场景验证**：

```
设备一删除任务A → sync
  → 本地 isDeleted=true, 上传云端 isDeleted=true
设备二 sync
  → 远程 isDeleted=true, 本地 isDeleted=false
  → 删除优先 → 设备二标记 isDeleted=true
  → 云端保留 isDeleted=true
下次任一方 sync
  → 双方 isDeleted=true → 从合并列表移除
  → 云端不再包含该任务
  → 本地 hardDelete 清理
```

### 1.3 实现步骤

#### 步骤 1.3.1：修改 `webdav_service.dart` - `_resolveConflict` 增加软删除处理

**文件**: `lib/services/webdav_service.dart`

**修改内容**:

```dart
/// 根据同步模式解决冲突（含软删除处理）
Task _resolveConflict(Task local, Task remote, SyncMode mode) {
  // 软删除优先处理：任一方删除即传播删除
  if (local.isDeleted || remote.isDeleted) {
    // 双方都删除 → 返回标记删除的版本（后续从合并列表移除）
    final deleted = local.isDeleted ? local : remote;
    deleted.isDeleted = true;
    return deleted;
  }

  // 双方都未删除 → 按原有模式处理
  switch (mode) {
    case SyncMode.autoMerge:
      return local.updatedAt.isAfter(remote.updatedAt) ? local : remote;
    case SyncMode.localFirst:
      return local;
    case SyncMode.remoteFirst:
      return remote;
  }
}
```

**验证方法**: 单元测试覆盖：本地删除+远程未删、远程删除+本地未删、双方都删除、双方都未删四种场景。

#### 步骤 1.3.5：修改 `task_list_screen.dart` - 同步后清理双方都删除的任务

**文件**: `lib/ui/screens/task_list_screen.dart`

**修改内容**: 在写回合并结果后，对本地存在但不在合并结果中的任务（即双方都删除的）执行 `hardDelete`：

```dart
// 在 mergedTasks 写回循环之后添加：
// 清理本地存在但合并结果中不存在的任务（双方都确认删除）
final mergedSyncIds = result.mergedTasks
    .where((t) => t.syncId != null)
    .map((t) => t.syncId!)
    .toSet();
for (final localTask in localTasks) {
  if (localTask.syncId != null &&
      !mergedSyncIds.contains(localTask.syncId)) {
    await dao.hardDeleteTask(localTask.id);
  }
}
```

**验证方法**: 双方都删除后同步，确认本地数据库中该任务被彻底清除。

**修改内容**: 在 `_TaskFormScreenState` 类中添加方法：

```dart
Future<void> _confirmDelete(BuildContext context) async {
  final confirmed = await showDialog<bool>(
    context: context,
    builder: (context) => AlertDialog(
      title: const Text('确认删除'),
      content: Text('确定要删除任务"${widget.task!.title}"吗？\n\n删除后可通过同步从其他设备恢复。'),
      actions: [
        TextButton(
          onPressed: () => Navigator.pop(context, false),
          child: const Text('取消'),
        ),
        TextButton(
          onPressed: () => Navigator.pop(context, true),
          style: TextButton.styleFrom(foregroundColor: Colors.red),
          child: const Text('删除'),
        ),
      ],
    ),
  );

  if (confirmed == true && context.mounted) {
    await _deleteTask(context);
  }
}

Future<void> _deleteTask(BuildContext context) async {
  try {
    final isar = await ref.read(isarProvider.future);
    final dao = TaskDao(isar);

    // 取消该任务的所有提醒通知
    await NotificationService().cancelTaskReminder(widget.task!);

    // 软删除任务
    await dao.softDeleteTask(widget.task!.id);

    if (context.mounted) {
      Navigator.pop(context); // 返回列表页
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('任务已删除')),
      );
    }
  } catch (e) {
    if (context.mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(
          content: Text('删除失败: $e'),
          backgroundColor: Colors.red,
        ),
      );
    }
  }
}
```

**验证方法**: 
1. 点击删除按钮 → 弹出确认对话框
2. 点击"取消" → 对话框关闭，任务不变
3. 点击"删除" → 任务被软删除，返回列表页，显示"任务已删除"提示

## 三、任务过期状态与提醒时间功能分离

### 3.1 问题分析

当前 `task_form_screen.dart` 中，`_addReminderTime` 方法使用 `_dueDate ?? DateTime.now()` 作为日期选择器的默认日期：

```dart
// 当前代码（第155行附近）：
final date = await showDatePicker(
  context: context,
  initialDate: _dueDate ?? DateTime.now(),  // 依赖 dueDate
  ...
);
```

这导致：
- 无截止日期的任务添加提醒时，默认日期是"今天"，不够直观
- 逻辑上提醒时间与截止日期耦合，但实际它们应该独立

### 3.2 功能分离目标

| 场景 | 当前行为 | 期望行为 |
|------|---------|---------|
| 无截止日期 + 添加提醒 | 默认日期为今天 | 默认日期为今天（保持不变，合理） |
| 有过期截止日期 + 添加提醒 | 日期选择器默认显示过期日期 | 日期选择器默认显示今天（过期日期无意义） |
| 有过期截止日期 + 已有提醒 | 提醒正常显示 | 提醒正常显示（不因过期而隐藏） |
| 提交任务 | `dueDate != null` 才调度提醒 | 保持不变（提醒调度逻辑不变） |

### 3.3 实现步骤

#### 步骤 3.3.1：修改 `_addReminderTime` - 日期选择器默认值优化

**文件**: `lib/ui/screens/task_form_screen.dart`

**修改内容**:

```dart
Future<void> _addReminderTime() async {
  // 默认日期：优先用截止日期（如果未过期），否则用今天
  final defaultDate = _dueDate != null && !_dueDate!.isBefore(
    DateTime(DateTime.now().year, DateTime.now().month, DateTime.now().day),
  )
      ? _dueDate!
      : DateTime.now();

  final date = await showDatePicker(
    context: context,
    initialDate: defaultDate,
    firstDate: DateTime.now(),
    lastDate: DateTime.now().add(const Duration(days: 365)),
  );
  if (date != null) {
    final time = await showTimePicker(
      context: context,
      initialTime: TimeOfDay.now(),
    );
    if (time != null) {
      setState(() {
        _reminderTimes.add(
          DateTime(date.year, date.month, date.day, time.hour, time.minute),
        );
        _reminderTimes.sort();
      });
    }
  }
}
```

**验证方法**: 
1. 编辑一个过期任务（截止日期 < 今天），点击添加提醒 → 日期选择器默认显示今天
2. 编辑一个未来任务（截止日期 >= 今天），点击添加提醒 → 日期选择器默认显示截止日期
