## 开发任务

### 任务 1：通知服务跨平台适配（🔴 严重）

**问题**：`flutter_local_notifications` 不支持 Windows 和 Linux，直接编译会报错。

**方案**：创建平台感知的通知服务抽象层，不支持通知的平台优雅降级。

**具体步骤**：

1.1 创建 `lib/services/notification_service_interface.dart`
- 定义 `NotificationServiceBase` 抽象类
- 抽象方法：`initialize()`、`scheduleTaskReminder()`、`cancelTaskReminder()`、`showNotification()`、`rescheduleAllReminders()`

1.2 创建 `lib/services/notification_service_stub.dart`
- 实现 `NotificationServiceBase`，所有方法为空操作（no-op）
- 用于 Windows/Linux/Web 等不支持本地通知的平台

1.3 修改 `lib/services/notification_service.dart`
- 改为实现 `NotificationServiceBase` 的具体类
- 保持现有 Android/iOS/macOS 逻辑不变

1.4 创建 `lib/services/notification_service_factory.dart`
- 根据 `Platform` 或 `kIsWeb` 返回对应实现
- Android/iOS/macOS → 真实通知服务
- Windows/Linux/Web → Stub 空实现

1.5 修改 `lib/main.dart`
- 使用工厂方法获取通知服务实例

1.6 在 Windows/Linux 的设置页面提示用户
- 通知功能不可用时，显示"当前平台不支持本地通知提醒"

### 任务 2：Android 通知权限完善（🔴 严重）

**问题**：Android 13+ 需要运行时请求 `POST_NOTIFICATIONS` 权限，Android 12+ 需要 `SCHEDULE_EXACT_ALARM` 权限。

**具体步骤**：

2.1 修改 `android/app/src/main/AndroidManifest.xml`
- 添加 `<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>`
- 添加 `<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>`
- 添加 `<uses-permission android:name="android.permission.USE_EXACT_ALARM"/>`
- 添加 `<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>`

2.2 添加 `permission_handler` 依赖到 `pubspec.yaml`
```yaml
permission_handler: ^11.3.0
```

2.3 修改 `lib/main.dart` 或 `notification_service.dart`
- 在初始化通知服务时请求 `POST_NOTIFICATIONS` 权限
- 处理用户拒绝权限的情况（显示提示）

2.4 修改 `android/app/build.gradle.kts`
- 设置 `minSdk = 21`（确保最低 API 21，当前使用 flutter.minSdkVersion）

### 任务 3：macOS 网络权限修复（🔴 严重）

**问题**：macOS Release entitlements 缺少 `com.apple.security.network.client`，导致 WebDAV 同步和 AI 聊天无法联网。

**具体步骤**：

3.1 修改 `macos/Runner/Release.entitlements`
- 添加 `<key>com.apple.security.network.client</key><true/>`
- 与 DebugProfile.entitlements 保持一致

3.2 修改 `macos/Runner/DebugProfile.entitlements`
- 确认 `com.apple.security.network.client` 已存在（当前缺失）

### 任务 4：文件导入导出跨平台适配（🟡 中等）

**问题**：`data_management_screen.dart` 直接使用 `dart:io` 的 `File` 和 `Platform`，Web 平台不可用。

**具体步骤**：

4.1 修改 `lib/ui/screens/data_management_screen.dart`
- 将 `import 'dart:io'` 改为条件导入
- 使用 `file_picker` 的 `saveFile` + `bytes` 参数替代 `File.writeAsString`
- 导入时使用 `file_picker` 的 `readFile` 或 `bytes` 属性替代 `File.readAsString`
- 移除对 `Platform.pathSeparator` 的依赖

4.2 创建 `lib/services/file_service.dart`（可选）
- 抽象文件读写操作
- 移动端/桌面端使用 `dart:io`
- Web 端使用 `file_picker` 的 bytes API

### 任务 5：桌面端响应式布局适配（🟡 中等）

**问题**：桌面端使用移动端 `BottomNavigationBar`，屏幕空间利用率低。

**方案**：根据屏幕宽度自动切换导航模式。

**具体步骤**：

5.1 创建 `lib/ui/components/adaptive_scaffold.dart`
- 窄屏（< 600dp）：`BottomNavigationBar`
- 宽屏（≥ 600dp）：`NavigationRail` + 内容区

5.2 修改 `lib/main.dart`
- 替换 `BottomNavigationBar` 为 `AdaptiveScaffold`
- 保持 4 个 tab 不变

5.3 修改各屏幕的布局
- 桌面端利用宽屏空间，任务列表使用双列/三列布局
- 聊天界面桌面端限制最大宽度（如 800dp），居中显示

### 任务 6：应用名称和包名规范化（🟡 中等）

**问题**：各平台应用名称不统一，Android 包名为 `com.example.catodo`。

**具体步骤**：

6.1 统一应用名称为 `Catodo`
- Android：修改 `android/app/src/main/AndroidManifest.xml` 的 `android:label`
- Windows：修改 `windows/runner/main.cpp` 的窗口标题
- macOS：修改 `macos/Runner/Configs/AppInfo.xcconfig` 的 `PRODUCT_NAME`
- Linux：修改 `linux/my_application.cc` 的标题
- Web：修改 `web/index.html` 的 `<title>` 和 `web/manifest.json` 的 `name`/`short_name`

6.2 修改 Android 包名（可选，建议发布前完成）
- 将 `com.example.catodo` 改为 `com.catodo.app` 或自定义域名
- 同步修改 `android/app/build.gradle.kts` 的 `applicationId`
- 同步修改 `android/app/src/main/kotlin/` 目录结构

### 任务 7：桌面端窗口配置（🟢 低）

**问题**：桌面端窗口无最小尺寸约束，用户可以缩放到极小导致 UI 错乱。

**具体步骤**：

7.1 添加 `window_manager` 依赖到 `pubspec.yaml`
```yaml
window_manager: ^0.4.0
```

7.2 修改 `lib/main.dart`
- 桌面端初始化时设置窗口最小尺寸（如 400x600）
- 设置窗口标题为 `Catodo`
- 设置默认窗口大小（如 800x600）

7.3 注意：`window_manager` 仅在桌面端使用，需要条件导入或平台判断

### 任务 8：Linux 背景色修复（🟢 低）

**问题**：Linux 窗口背景色为黑色，与浅色主题冲突。

**具体步骤**：

8.1 修改 `linux/runner/my_application.cc`
- 将 `gdk_rgba_parse(&background_color, "#000000")` 改为 `gdk_rgba_parse(&background_color, "#FFFFFF")`

### 任务 9：Web 平台兼容性评估（🟡 中等）

**问题**：Isar 不支持 Web，当前项目无法在 Web 上运行。

**方案选择**：
- **方案 A**：暂不支持 Web 平台，在 `flutter build` 时排除 Web
- **方案 B**：Web 端使用 IndexedDB/SharedPreferences 替代 Isar
- **方案 C**：使用 Isar 的 Web 支持分支（实验性）

**建议**：当前采用方案 A，Web 支持作为长期规划。原因：
1. Isar Web 支持仍不完善
2. 本地通知在 Web 上不可用
3. 文件系统操作受限
4. 投入产出比低

当前选择方案 A
