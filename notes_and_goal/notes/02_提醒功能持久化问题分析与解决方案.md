# 提醒功能持久化问题分析与解决方案

## 一、问题描述

用户反馈：重新打开软件时，之前设置的提醒不见了。

## 二、问题分析

### 2.1 数据持久化层面

通过检查代码，`reminderTimes` 字段在数据模型中已经正确定义：

```dart
// lib/models/task.dart
List<DateTime> reminderTimes = [];
```

并且在 Isar 数据库生成的代码中（`task.g.dart`），该字段被正确定义为 `dateTimeList` 类型，支持序列化和反序列化：

```dart
r'reminderTimes': PropertySchema(
id: 8,
name: r'reminderTimes',
type: IsarType.dateTimeList,
),
```

**结论**：`reminderTimes` 数据本身是可以正确持久化到数据库并在重启后恢复的。

### 2.2 通知调度层面

问题出在通知调度的机制上：

1. **通知存储位置**：提醒通知是通过 `flutter_local_notifications` 插件调度到操作系统层面的
2. **重启后状态**：当应用重启时，操作系统中已调度的通知可能丢失或失效
3. **当前初始化逻辑**：
    ```dart
    // lib/main.dart
    await NotificationService().initialize();
    ```
    这里只是初始化通知插件，但**没有重新调度之前设置的提醒**

### 2.3 问题根因

**核心问题**：`reminderTimes` 数据虽然持久化在数据库中，但通知调度是一次性的操作，不会在应用重启时自动恢复。

## 三、解决方案

### 3.1 方案概述

在应用启动完成后，遍历所有任务，对包含有效提醒时间的任务重新调度通知。

### 3.2 具体实现步骤

1. **创建重新调度提醒的方法**：在 `NotificationService` 中添加批量调度方法
2. **在应用启动时调用**：在 `main.dart` 中，数据库初始化完成后触发重新调度
3. **过滤条件**：只调度未完成且提醒时间在未来的任务

### 3.3 代码修改计划

#### 修改 `lib/services/notification_service.dart`

添加批量调度方法：

```dart
Future<void> rescheduleAllReminders(List<Task> tasks) async {
for (var task in tasks) {
    if (task.isCompleted) continue;
    if (task.reminderTimes.isEmpty) continue;
    
    await scheduleTaskReminder(task);
}
}
```

#### 修改 `lib/main.dart`

在数据库初始化完成后调用重新调度：

```dart
data: (isar) {
// 重新调度所有提醒
final tasks = isar.tasks.filter().isCompletedEqualTo(false).findAll();
NotificationService().rescheduleAllReminders(await tasks);
return Scaffold(...);
}
```

## 四、测试标准

1. **数据持久化测试**：设置提醒后重启应用，`reminderTimes` 字段应正确恢复
2. **通知调度测试**：设置提醒后重启应用，通知应在指定时间正常触发
3. **边界条件测试**：
    - 已完成任务不应重新调度
    - 过期的提醒时间不应重新调度
    - 无提醒时间的任务不应调度

## 五、风险评估

| 风险点 | 影响 | 缓解措施 |
|-------|------|---------|
| 大量任务导致启动延迟 | 启动时遍历所有任务可能耗时 | 只处理未完成且有提醒的任务 |
| 重复调度 | 同一任务多次调度 | 使用固定的 notificationId 规则（task.id * 10 + index） |
| 时间精度问题 | 时区转换可能导致时间偏差 | 使用 `tz.local` 确保本地时区一致性 |
